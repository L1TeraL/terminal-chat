# Terminal Chat

Простой многопользовательский терминальный чат на Python с клиент-серверной архитектурой.

Проект создан для практики работы с TCP-сокетами, многопоточностью, протоколами обмена сообщениями и синхронизацией потоков.

## Возможности

* TCP-соединение между клиентом и сервером
* Несколько пользователей одновременно
* Уникальные имена пользователей
* Валидация username
* Обмен сообщениями между клиентами
* Системные сообщения о подключении и отключении пользователей
* Команда `/online` для просмотра пользователей онлайн
* Команда `/quit` для выхода из чата
* Корректное завершение через `Ctrl+C`
* Обработка потерь соединения
* JSON-протокол сообщений
* Разделение сообщений TCP-потока с помощью `\n`
* Потокобезопасный реестр подключённых клиентов

## Запуск сервера

Из корневой директории проекта:

```bash
python3 -m server.server
```

После запуска сервер начнёт ожидать подключения:

```text
[SERVER] Listening on 127.0.0.1:5000
```

## Запуск клиента

В отдельном терминале:

```bash
python3 -m client.client
```

После подключения клиент попросит указать имя:

```text
[SERVER] Connected.
Enter username: dan
[SERVER] Welcome, dan!
```

Для подключения нескольких пользователей необходимо запустить несколько экземпляров клиента.

## Команды

### `/online`

Показывает пользователей, находящихся онлайн.

```text
/online
```

Пример:

```text
[SERVER] Online 2
         - dan
         - ann
```

### `/quit`

Завершает подключение к серверу:

```text
/quit
```

Также клиент корректно обрабатывает `Ctrl+C`.

## Архитектура

Проект разделён на три основные части:

### `client`

Отвечает за:

* подключение к серверу;
* ввод пользователя;
* отправку сообщений;
* получение сообщений;
* обработку команд сервера;
* завершение соединения.

Для получения сообщений используется отдельный поток.

### `server`

Отвечает за:

* принятие TCP-соединений;
* создание отдельного потока для каждого клиента;
* обработку команд;
* регистрацию пользователей;
* рассылку сообщений;
* отключение клиентов.

### `shared`

Содержит код, общий для клиента и сервера.

В частности, `protocol.py` отвечает за формат сообщений:

```json
{
    "command": "CHAT",
    "payload": "Hello!"
}
```

Каждый пакет завершается символом `\n`, что позволяет корректно разделять сообщения внутри TCP-потока.

## Обработка TCP-потока

TCP не сохраняет границы отдельных сообщений. Поэтому один вызов `recv()` может получить:

* часть сообщения;
* одно сообщение;
* несколько сообщений сразу.

Для решения этой проблемы используется буфер:

```text
TCP stream
    ↓
buffer
    ↓
message\n
    ↓
decode
    ↓
process
```

Клиент и сервер накапливают полученные данные в буфере и обрабатывают сообщения только после обнаружения `\n`.

## Синхронизация

Реестр клиентов защищён с помощью `threading.Lock`, поскольку несколько потоков сервера могут одновременно обращаться к нему.

Для ожидания результата авторизации на клиенте используется `Queue`, а `threading.Event` используется для управления завершением потоков.
