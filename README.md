# Terminal Chat

Многопользовательский терминальный чат на Python с клиент-серверной архитектурой.

Проект создан для практики работы с TCP-сокетами, многопоточностью, JSON-протоколами, синхронизацией потоков, SQLite и автоматическим тестированием.

## Возможности

* TCP-соединение между клиентом и сервером
* Несколько пользователей одновременно
* Уникальные имена пользователей
* Валидация username
* Обмен сообщениями между клиентами
* История последних сообщений
* Хранение истории в SQLite
* Получение последних 20 сообщений при подключении
* Системные сообщения о подключении и отключении пользователей
* Команда `/online` для просмотра пользователей онлайн
* Команда `/help` со списком команд
* Команда `/quit` для выхода из чата
* Корректное завершение через `Ctrl+C`
* Обработка потери соединения
* JSON-протокол сообщений
* Разделение сообщений TCP-потока с помощью `\n`
* Потокобезопасный реестр подключённых клиентов
* Unit-тесты и интеграционные тесты
* Тестирование взаимодействия нескольких клиентов с сервером

## Запуск сервера

Из корневой директории проекта:

```bash
python3 -m server.server
```

После запуска сервер начинает ожидать подключения:

```text
[SERVER] Listening on 127.0.0.1:5000
```

## Запуск клиента

В отдельном терминале:

```bash
python3 -m client.client
```

После подключения клиент попросит указать username:

```text
Username ❯ Alex
```

После успешной авторизации отображаются пользователи онлайн и история последних сообщений.

Для подключения нескольких пользователей необходимо запустить несколько экземпляров клиента.

## Команды

### /online

Показывает пользователей, находящихся онлайн:

```text
/online
```

### /help

Показывает доступные команды:

```text
/help
```

### /quit

Завершает подключение к серверу:

```text
/quit
```

Также клиент корректно обрабатывает Ctrl+C.

## История сообщений

Все сообщения чата сохраняются в локальной SQLite-базе данных.

Используется таблица:

```text
chat_messages
├── id
├── username
├── message
└── created_at
```

При подключении пользователя сервер отправляет последние 20 сообщений.

История отображается после блока авторизации и списка пользователей:

```text
LOGIN SUCCESS
Online Users
Chat History
```

Для получения истории используется запрос последних сообщений с последующей сортировкой в хронологическом порядке.

## Архитектура

Проект разделён на три основные части.

### client

Отвечает за:

подключение к серверу;
ввод username;
авторизацию;
отправку сообщений;
получение сообщений;
отображение истории;
обработку команд;
завершение соединения.

Получение сообщений выполняется в отдельном потоке, чтобы клиент одновременно мог принимать сообщения от сервера и ожидать пользовательский ввод.

### server

Отвечает за:

принятие TCP-соединений;
создание отдельного потока для каждого клиента;
обработку команд;
регистрацию пользователей;
валидацию username;
рассылку сообщений;
отправку истории;
управление отключением клиентов.

### shared

Содержит код, используемый клиентом и сервером.

`protocol.py` отвечает за формат сообщений между клиентом и сервером.

Пример пакета:

```json
{
    "command": "CHAT",
    "payload": "Hello!"
}
```

Каждый пакет заканчивается символом `\n`.

## Протокол

В проекте используются команды:

`SET_NAME`
`CHAT`
`INFO`
`ERROR`
`QUIT`
`USER_LIST`
`ONLINE`
`LOGIN_OK`
`LOGIN_FAILED`
`CHAT_HISTORY`

Протокол использует JSON:

```json
{
    "command": "...",
    "payload": "..."
}
```

Для разделения сообщений внутри TCP-потока используется `\n`.

## Обработка TCP-потока

TCP не сохраняет границы отдельных сообщений. Поэтому один вызов `recv()` может получить:

часть сообщения;
одно сообщение;
несколько сообщений.

Для решения этой проблемы клиент и сервер используют буфер:

```text
TCP stream
    ↓
buffer
    ↓
message\n
    ↓
decode
    ↓
process
```

Данные накапливаются в буфере до обнаружения `\n`, после чего пакет декодируется и обрабатывается.

## Синхронизация

Реестр подключённых клиентов защищён с помощью `threading.Lock`, поскольку несколько потоков сервера могут одновременно обращаться к нему.

На клиенте:

Queue используется для передачи результатов авторизации между потоками;
отдельная Queue используется для получения истории сообщений;
threading.Event используется для управления завершением потоков.
